# 大衍帝国

一个联网多人在线的架空王朝权谋经营模拟器。玩家从最基层的书办起步，沿十八级官阶向上攀爬，
在正当权力与地下权力之间做取舍，经营人脉、结党博弈，直至入阁拜相。

> **世界观声明**：本作的时代背景、王朝、官署、官阶、职名全部为架空虚构，与现实任何国家、
> 政权、机构、职官体系无关，不构成对任何现实的指涉或映射。

## 快速开始

```bash
cd game
npm install
npm start
# 打开 http://localhost:8787
```

首次启动会自动建库、生成占缺表、写入开朝邸报。数据库文件在 `data/empire.db`。

首次启动会自动铺设 **56 员朝廷旧人**（朝臣）与四个党派，因此新服一开局便是一个有人、
有缺、有恩怨的朝堂，而不是空场。

```bash
npm run dev     # 热重载
npm test        # 全部测试（逻辑层不需要服务在跑）
npm run smoke   # 仅后端接口测试（需先启动服务）
npm run test:ui # 仅前端 jsdom 测试（需先启动服务）
npm run reset   # 清空存档重开（会二次确认）
```

## 单机版网页

不想起服务器时，直接双击根目录的 **`daiyan-offline.html`** —— 零依赖、零联网、
零构建，浏览器里就是一整个朝堂。

- **同源数值**：十八级官阶、54 个竞争性缺额、20 条行动、8 类事件、56 员朝臣与四党，
  全部与联机版取自同一套数值（弹劾警戒 78 / 拉满 22%，落马降 1 级、圣眷剩四成）。
- **朝臣照旧自己动**：每回合自行积累、铨选迁转、爆丑闻、乞休；你动他，他反制；
  有旧怨或出自激进党的，还会主动构陷你 —— 构陷的公开风闻不点名。
- **单机专属**：5 种出身（寒门 / 书香 / 商贾 / 胥吏 / 勋戚）带来不同起手资源，
  可「告病致仕」清零重来，官阶巅峰留在案底。
- **存档**：自动存在浏览器 localStorage，另有 3 个手动档位，支持导出/导入 JSON。
- **节奏**：手动点「推进一回合」，也可在档位菜单里开自动推进（每 8 秒一回合）。

> 联机版用 SQLite + Socket.IO + JWT，单机版把这些全部换成了内存状态与 localStorage，
> 玩法逻辑不变，只是没有真人对手与公议频道。

测试：`npm run test:offline`（jsdom 驱动真实页面，46 项断言）。

## 玩法概要

每个回合（默认 3 分钟）自动结算一次，**离线照常结算**：

- 发放俸禄（按官阶）
- 政令点回满
- 精力恢复 12 点、暴露度自然衰减 7 点
- 圣眷被暴露度持续侵蚀（`暴露度 × 0.18 × 官阶系数`）
- 在任回合数 +1
- 约 10% 概率触发随机事件

核心循环：**积累资历 → 递呈铨选 → 占缺升迁 → 扩大势力 → 经营关系 → 争夺有限高位**。

### 属性

| 属性 | 含义 |
|---|---|
| 政绩 merit | 明线积累的办事成效，铨选的主项 |
| 声望 renown | 清议评价，影响铨选成算与抵抗构陷 |
| 权谋 guile | 暗线行动的燃料，也是暗线的防御力 |
| 人脉 network | 关系网络的厚度，立党与举荐的门槛 |
| 圣眷 favor | 上面那位对你的观感，弹劾时的护身符 |
| 暴露 exposure | 暗线痕迹的累积，越线后弹劾风险攀升，且持续侵蚀圣眷 |

**功绩分**（铨选依据）= `政绩 + 声望×0.6 + 人脉×0.8 + 圣眷×1.2`

### 资源

政令 mandate（每回合回满）· 银两 silver · 影响力 influence

## 官阶体系

十八级，自从九品书办至正一品首辅。**基层不限员额，从七品以上逐缺竞争**，
全服共 54 个竞争性缺额，缺满即须候补——这是多人在线博弈的核心。

> 54 是基数。缺额还会按在册真人数动态放量（`SLOT_SCALE`：县令至侍郎各阶配
> 0.12–0.4 缺/人，30 人时全服约 77 缺），以免少数几个缺把晋升通道堵死；
> 中枢高位（从三品及以上）刻意不放量——顶层必须稀缺，那是博弈的靶心。

| 品级 | 官职 | 员额 | 品级 | 官职 | 员额 |
|---|---|---|---|---|---|
| 从九品 | 书办 | 不限 | 正五品 | 郎中 | 12 |
| 正九品 | 主簿 | 不限 | 从四品 | 员外郎 | 12 |
| 从八品 | 县丞 | 不限 | 正四品 | 侍郎 | 6 |
| 正八品 | 典史 | 不限 | 从三品 | 大理寺卿 | 1 |
| 从七品 | 县令 | 3 | 正三品 | 左都御史 | 1 |
| 正七品 | 州判 | 2 | 从二品 | 尚书 | 6 |
| 从六品 | 州同知 | 2 | 正二品 | 群辅 | 4 |
| 正六品 | 郡丞 | 2 | 从一品 | 次辅 | 1 |
| 从五品 | 郡守 | 1 | 正一品 | 首辅 | 1 |

**衙门**：县衙、郡府、州衙（地方）；铨曹、度支曹、仪制曹、武备曹、刑名曹、营造曹、
都察院、翰林院、大理寺、内阁（中枢）。

**铨选条件**：功绩分达到下一阶门槛 + 在任满 3 回合 + 该阶有空缺。
成功率受功绩溢出、圣眷、声望正向影响，受暴露度轻微负面影响，区间 5%–95%。

缺额满员时，真人可挤走该阶上**权势最弱的朝臣**（朝臣之间不互相挤）——
否则开服后期高阶长期无缺，玩家只能干等。

**休致**：连续 3 天不视事的高官会被朝廷休致，腾出缺来。

## 两条路径

### 正当权力（明线）

| 行动 | 消耗 | 说明 |
|---|---|---|
| 推行新政 | 政令 3 | 政绩主来源，25% 概率受阻 |
| 调配钱粮 | 政令 2 | 银两 + 政绩，随官阶放大 |
| 巡查地方 | 政令 2 | 政绩 + 声望，耗精力 |
| 上书言事 | 政令 2 | 圣眷为主，看声望加成 |
| 考核属吏 | 政令 2 | 人脉 + 权谋，最温和的立威 |
| 举荐人才 | 政令 3 + 银 60 | 建立**门生**关系 |
| 求恩主举荐 | 银 150 | 圣眷 +，消耗恩主交情 |
| 自陈求进 | 政令 4 | 高收益高波动，看圣眷 |

### 地下权力（暗线）

**每一次暗线运作都会累积暴露度。暴露度越过警戒线（78）后，弹劾风险开始线性上升，
拉满时每次行动结算后有 22% 概率被台谏掀翻；圣眷不足便镌级降职。**

越过警戒线不等于必落马 —— 这是刻意设计的**软阈值**：风险随痕迹加深而爬升，
让你有机会在风声变紧时收手、花钱消弭痕迹，而不是"攒到 100 就一刀切"。

| 行动 | 消耗 | 说明 |
|---|---|---|
| 密谋构陷 | 权谋 14 × 官阶系数 | 削减目标政绩与圣眷，自己也进账；失败则暴露大增并结死敌 |
| 收买把柄 | 银 200 | 权谋 +，留下痕迹 |
| 风闻奏事 | 政令 2 + 银 80 | 借清议削目标声望 |
| 消弭痕迹 | 银 90 | 暴露度 −30（±25%），一次只买回约三个回合的痕迹 |
| 暗中挖角 | 银 260 | 削目标人脉，转为自己人脉 |
| 暗中输诚 | 银 300 | 越过正途换圣眷 |

### 关系经营（社交）

| 行动 | 消耗 | 说明 |
|---|---|---|
| 赠礼 | 银 80 | 结一份善缘，交情 +14 |
| 设宴结交 | 银 130 | 人脉 + 声望 |
| 修书通问 | 政令 1 | 不费银钱，只费心思 |
| 缔结姻亲 | 银 420 | 结成**姻亲**，交情上限最高，也连坐最深 |
| 托付心腹 | 银 160 + 政令 1 | 结成**心腹**，可替你分担暗线痕迹 |

### 仕途

| 行动 | 消耗 | 说明 |
|---|---|---|
| 告病致仕 | — | 自请去职，功名人脉恩怨一并归零，从书办重头再来 |

暗线行动不会写进公开邸报，只在你的私档留痕；但每次运作都会在邸报上留下一句
「【风闻】京师近日颇有异动，然查无实据」——所有人都看得到，没人知道是谁。

### 弹劾审判

每次行动结算后清算：先算风险，再掷骰。（朝臣则是在 `npcTick` 里每回合清算一次。）

```
风险 = min(1, (暴露度 − 78) / 22) × 0.22      // 78 以下为 0，拉满为 0.22
存活率 = 圣眷 / (圣眷 + 70×官阶系数) + 0.18    // 夹在 [0.12, 0.8]
```

圣眷的标尺随官阶放大 —— 高位者圣眷动辄上千，若直接代入原式则弹劾必活，
暗线在高阶就成了无风险套利。上限压到 0.8，是为了让"圣眷再厚也压不死台谏"。

- **过关**：暴露度 −55，圣眷 −35×官阶系数，声望 −10×官阶系数
- **落马**：降 **1** 级，暴露度重置为 45，圣眷剩四成（×0.4），释放所占缺额；
  姻亲与心腹一并连坐（姻亲圣眷 −14、交情 −10；心腹的东家圣眷与人脉按 0.6 折算受损）

> 落马只降 1 级，是跑批调出来的。早先「从六品以上降 2 级」看似更有威慑，
> 实测却把暗线打成了**弹劾循环**：高位每升一级要十余回合，一次落马两级的坑填不回来，
> 长局中权臣均阶反而低于循吏（600 回合 11.6 vs 11.9，80% 被弹劾过）。
> 降 1 级既保留了"一朝翻船、前功尽弃"的分量，又让暗线爬得快这件事真正兑现。

此外，**暴露度每回合持续侵蚀圣眷**（`暴露度 × 0.18 × 官阶系数`）。这是暗线的日常代价：
即便从没被弹劾，长期浸在黑水里的人，圣眷也会一点点漏掉。

## 关系与派系

### 关系类型

| 类型 | 含义 |
|---|---|
| 恩主 patron | 提携你的人，倒台会牵连你 |
| 门生 protege | 你举荐的人 |
| 盟友 ally | 共进退 |
| 政敌 rival | 同路相争 |
| 死敌 nemesis | 构陷失败后结下，不共戴天 |
| 姻亲 kin | 联姻结成，交情上限最高 |
| 心腹 confidant | 可托付隐秘之事 |

关系强度 0–100，通过赠礼、修书、设宴、联姻、托付心腹、举荐等行动增减。

### 派系宗旨

| 宗旨 | 政绩 | 声望 | 权谋 | 暴露 |
|---|---|---|---|---|
| 清流 | ×1.0 | ×1.35 | ×0.6 | ×1.6 |
| 实务 | ×1.35 | ×0.85 | ×1.0 | ×1.0 |
| 守成 | ×0.85 | ×1.0 | ×0.9 | ×0.7 |
| 激进 | ×1.6 | ×1.1 | ×1.25 | ×1.35 |

立党门槛：人脉 ≥ 40 且银两 ≥ 300。党势 = 党员权势之和，每回合重算。
党魁可输金入公库，党员可退党（损失人脉与声望）。

### 随机事件

8 类模板（河决、风闻、缺出、厚礼、岁歉、文会、座师出事、密札），
按官阶区间加权抽取，每回合约 10% 概率触发。每个事件三选一，
选项普遍存在「清名 / 实利 / 把柄」的三角取舍。

## 朝廷旧人（朝臣）

新服不是空场。开朝时会自动铺设 **56 员朝臣** 与 **4 个党派**，
占去 54 个竞争性缺额中的 32 个，留下 22 缺给玩家攀爬。

| 官阶 | 铺设 | 官阶 | 铺设 |
|---|---|---|---|
| 正一品 首辅 | 1 / 1 | 正五品 郎中 | 6 / 12 |
| 从一品 次辅 | 1 / 1 | 从四品 员外郎 | 6 / 12 |
| 正二品 群辅 | 3 / 4 | 正四品 侍郎 | 4 / 6 |
| 从二品 尚书 | 4 / 6 | 从三品 大理寺卿 | 1 / 1 |
| 正三品 左都御史 | 1 / 1 | 从五品 郡守 | 1 / 1 |
| 正六品 郡丞 | 1 / 2 | 从六品 州同知 | 1 / 2 |
| 正七品 州判 | 1 / 2 | 从七品 县令 | 1 / 3 |

另有 24 员基层朝臣（书办至典史）在州县当差。

**开局四党**

| 党名 | 宗旨 | 党魁 |
|---|---|---|
| 清议堂 | 清流 | 由党内官阶最高者自动出任 |
| 度支局 | 实务 | 同上 |
| 守拙会 | 守成 | 同上 |
| 新政社 | 激进 | 同上 |

党魁自动与 6 名党员结成恩主/门生关系，四党党魁两两互为政敌——
开局就有一张现成的关系网可供玩家钻营或利用。

**朝臣每回合自行其是**（`npcTick`）：

- 积累政绩、声望、人脉、圣眷、权谋（受所属党派宗旨的乘数影响）
- 领俸禄、政令回满、暴露度自然衰减
- 0.35% 概率爆出丑闻（暴露度 +35~70），越过警戒线后按软阈值遭弹劾镌级
- 年资过深或小概率乞休，腾出缺额
- 达标的会递呈铨选，成功则迁转并载入邸报
- 回合末尾补员（`replenishCourt`）：空缺一开就补新血，故朝臣记录只增不删，
  去位者仅置 `retired = 1` 并退出党派

**反制**：玩家以暗线手段（密谋构陷、收买把柄、风闻奏事、暗中挖角）对付朝臣时，
权势足够的朝臣会反手一击——削你的政绩与圣眷、推高你的暴露度，并结下仇怨。
官职越高，反制越重。**朝臣不是待宰的 NPC，是活人。**

**主动出招**（`npcSocialTick`）：反制是被动的——你不动他，他就不动你。
所以另有一层：每回合至多一名朝臣对一名玩家主动出手，按官阶加权挑选出手者，
并优先挑与之有往来的人（无缘无故的提携与无缘无故的敌意都不成立）。

| 招法 | 触发条件 | 效果 |
|---|---|---|
| 举荐 | 与你已有交情（恩主/门生/盟友/心腹） | 圣眷 +、声望 +，就此结成恩主—门生 |
| 拉拢 | 你有党可投而他所在党派有意招揽 | 人脉 +、圣眷 +，并给出投效的路径 |
| 构陷 | 与你已结怨（政敌/死敌），或出手者出自「手黑」的党派 | 政绩 −、圣眷 −、痕迹 +，并结下仇怨 |

- 出手频率随在朝人数上升但封顶（每回合至多一人）：一回合一条消息已是打扰，再多就成噪音
- 「手黑」= 宗旨 `guileMul ≥ 1.2`（即**激进**的新政社）。他们连盟友也留两成翻脸的可能，
  否则每人拉拢过一次之后就永远只举荐，朝局会退化成一片和气
- **构陷的公开风闻不点名**：全服看得到「京师近日颇有异动」，但没人知道是谁下的手；
  只有受害者本人的私档里写明是谁
- 构陷有失手判定（攻方权势 vs 守方清望）。失手只在邸报上留下一句语焉不详的风闻

**与玩家的边界**

- 朝臣不可登录（`password_hash` 为占位符，登录接口会拒绝）
- 朝臣不显示为在线，名录中以「朝臣」标签区分
- 朝臣不受「久不视事即休致」的清理规则约束，只按自己的年资与运气去留
- 朝臣的权谋值与暴露度同样不对外暴露
- 朝臣的随机源（`prand`）与 `Math.random` 分离，可用 `NPC_SEED` 环境变量钉死，
  便于测试与跑批复现；线上不设则每次开朝都是一张新面孔

**调参**：`server/game/npc.js` 顶部的 `COURT_PLAN`（各阶铺设数）、`JUNIOR_PLAN`（基层人数）、
`FACTION_PLAN`（党派与宗旨）、`SURNAMES` / `GIVEN`（姓名池）。

> 分党按官阶分层随机，但**四党在各阶都要有人**。早先高位只派清流/守成/实务，
> 新政社永远到不了中枢，于是「手黑」这一路在朝堂上始终没有分量——
> 实测按官阶加权挑出手者时激进仅占 6%，构陷这条路等于形同虚设。修正后为 20%。

## 技术架构

```
game/
├── package.json
├── daiyan-offline.html   单机版：单文件、双击即玩、零依赖
├── server/
│   ├── index.js              服务入口：HTTP + Socket.IO + 回合循环
│   ├── db.js                 SQLite 连接、Schema、world 状态
```

**技术选型**

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | Node.js ≥ 20（ESM） | 单进程承载状态机与回合循环 |
| HTTP | Express 4 | 轻量、生态成熟 |
| 实时 | Socket.IO 4 | 自带断线重连与房间 |
| 存储 | SQLite（better-sqlite3） | 零运维、WAL 并发读、单文件备份 |
| 鉴权 | JWT（jti 唯一）+ bcryptjs | 无状态令牌 + 会话表可吊销 |
| 前端 | 原生 HTML/CSS/JS | 无构建步骤，改完即生效 |

**并发安全**：所有写操作走 `better-sqlite3` 的同步事务（`db.transaction`），
Node 单线程模型下天然串行，不存在占缺竞态。行动执行、铨选、事件结算全部在事务内完成。

## 数据库设计

SQLite，WAL 模式，外键开启。表结构见 `server/db.js`。

| 表 | 用途 | 关键字段 |
|---|---|---|
| `players` | 玩家与朝臣主体 | `rank_id` `office_key` `faction_id` `stats`(JSON) `resources`(JSON) `tenure` `cooldowns`(JSON) `career_peak` `history`(JSON) `is_npc` |
| `sessions` | 令牌会话 | `token`(PK) `player_id` `expires_at` |
| `relations` | 有向关系边 | `from_id` `to_id` `type` `strength`，唯一键 `(from,to,type)` |
| `factions` | 党派 | `name` `doctrine` `leader_id` `treasury` `power` |
| `office_slots` | 占缺表 | `rank_id` `organ_key` `slot_index` `holder_id`，唯一键 `(rank,organ,slot)` |
| `action_log` | 行动审计 | `player_id` `action_key` `ok` `detail`(JSON) |
| `gazette` | 邸报 | `scope`(global/private) `player_id` `kind` `text` |
| `pending_events` | 待决事件 | `player_id` `template` `payload` `resolved` |
| `direct_messages` | 私函 | `from_id` `to_id` `text` `seen` |
| `world` | 全局状态 | `k` `v`（当前回合、开朝时间） |

**索引**：`players(rank_id)`、`players(is_npc, retired)`、`relations(from_id)`、`relations(to_id)`、
`action_log(created_at DESC)`、`gazette(created_at DESC)`、
`pending_events(player_id, resolved)`、`direct_messages(from_id, to_id, created_at DESC)`、
`direct_messages(to_id, seen)`。

**迁移**：`db.js` 内置幂等补列（`ensureColumn`），旧存档启动时自动补 `players.is_npc`
与 `direct_messages.seen`。依赖新列的索引刻意放在补列之后创建，否则旧库启动会直接报错。

**隐私设计**：`/api/players/:id` 返回的档案只暴露声望与人脉（对外可见的社会评价），
权谋值与暴露度仅本人可见——这是暗线博弈成立的前提。

### 备份

SQLite 是单文件，直接复制即可（WAL 模式下建议先 checkpoint）：

```bash
sqlite3 data/empire.db "PRAGMA wal_checkpoint(TRUNCATE);"
cp data/empire.db /backup/empire-$(date +%F).db
```

或在线备份：`sqlite3 data/empire.db ".backup /backup/empire.db"`

### 扩容说明

当前设计为**单进程**：回合循环、Socket.IO 房间状态、占缺事务都在进程内，
这是保证占缺无竞态的最简方案，单机可支撑数百至上千并发玩家。

若需横向扩展，按此路径演进：

1. SQLite → PostgreSQL（`server/db.js` 是唯一数据访问入口，替换驱动与方言即可）
2. 引入 `@socket.io/redis-adapter` 做多实例广播
3. 回合循环抽为独立 worker，用分布式锁保证只跑一份

## 调参与扩展

### 数值平衡跑批

```bash
node scripts/sim.js                          # 30 人 × 300 回合
node scripts/sim.js --players=30 --ticks=600
node scripts/sim.js --yield=1.05 --warn=78 --impeach=0.22 --brief   # 扫参
```

跑批用独立数据库（`data/sim-*.db`）与固定种子 LCG 随机源，结果可复现，
不触碰线上存档。它会检验四件事并给出裁决：

1. **晋升节奏** —— 均阶是否落在目标区间（下界 3；上界随回合数放宽：
   `min(14, 11 + (回合数 − 300) / 100)`，300 回合时为 11、400 为 12、600 为 14）
2. **顶层可达** —— 最高是否到得了第 12–17 级（300 回合以下不计，第 12 级实测约需 230 回合）
3. **缺额竞争** —— 竞争性官阶占用率是否 ≥ 60%
4. **暗线有代价但走得通** —— 权臣均阶高于循吏，且确有被弹劾者

受控实验设计：三条路线（循吏 / 干吏 / 权臣）共用同一套明线底子
（`policy` `allocate` `patrol` `memorial` `assess` `banquet`），
**唯一变量是暗线投入比例**（0% / 50% / 100%），这样跑出的差距才归因于暗线本身。

可覆盖的参数：`--players` `--ticks` `--seed` `--yield` `--warn` `--impeach` `--erosion` `--cover` `--tag`。
`--tag` 给跑批库加后缀，扫参时可并行多组而不互相踩踏；`--brief` 每组只打一行，
便于一次扫十几组参数。

#### 当前平衡基线

`yield=1.02 warn=78 rate=0.22 erosion=0.18 cover=68`，30 人，固定种子（结果可复现）：

| 回合 | 循吏（0% 暗线） | 干吏（50%） | 权臣（100%） |
|---|---|---|---|
| 400 | 10.0 / 13 · 0% | 10.6 / 14 · 20% | **11.1 / 15 · 30%** |
| 600 | 11.1 / 14 · 0% | 11.8 / 15 · 20% | **12.3 / 16 · 30%** |

（格式：均阶 / 最高阶 · 被弹劾者占比）

复现命令（内建种子 20260915，逐次运行输出一致）：

```bash
node scripts/sim.js --players=30 --ticks=400
node scripts/sim.js --players=30 --ticks=600
```

这正是设计要的形状：**两条路都通天，代价不同**。
权臣的均阶与天花板始终最高，但要付出三成的落马率 ——
暗线不是更稳，是**更陡**：上位快，掉得也狠。

> **这一版基线含朝臣主动出招**（举荐 / 拉拢 / 构陷）。加上这一层后，暗线一度反而
> 落后于明线（600 回合 11.6 vs 11.8）—— 因为走暗线的人必然与朝臣结怨，
> 于是被反复主动构陷，等于在弹劾之外又挨一重税。故把构陷的分量调轻于反制：
> 反制是玩家自己招惹来的，该重；主动构陷是朝堂上无端的恶意，该难受但不该压垮整条路。

> **扫参前必读**：朝臣的随机源由 `NPC_SEED` 环境变量控制。`sim.js` 会自动钉死它，
> 所以跑批可复现；若手动改动 `npc.js` 的播种方式，扫参读数会重新混入噪声
> （实测同参数两次运行权臣均阶相差 0.8 级）。

### 常用调参（`server/game/data.js` 的 `CONST` 与官阶系数）

```js
TICK_MS: 3 * 60 * 1000,   // 回合间隔
START_SILVER: 320,        // 初始银两
EXPOSURE_DECAY: 7,        // 每回合暴露度自然衰减
EXPOSURE_EROSION: 0.18,   // 暴露度对圣眷的持续侵蚀系数（暗线的日常代价）
IMPEACH_WARN: 78,         // 弹劾警戒线：越过此线风险才开始上升
IMPEACH_RATE: 0.22,       // 暴露拉满时，每次行动结算后被弹劾的概率
YIELD_BASE: 1.02,         // 官阶收益系数：每升一级，收益乘以这个数
```

**`YIELD_BASE` 是全局节奏的总阀门**。收益随官阶放大，才能让"升一级所需回合数"
在十八级里大致持平 —— 否则低位一回合一级、高位几十回合一级，中段就卡死了。
但它同时决定了整局快慢：调高则全员快速拜相，调低则高位长年空置。
（实测 1.18 → 600 回合全员拜相；1.06 → 400 回合均阶 11.9 仍偏快；1.02 → 400 回合均阶 10.6，落在目标区间。）

### 加一条新行动

在 `server/game/actions.js` 里加一项即可，前端自动出现在对应路径分组下：

```js
export const OPEN_ACTIONS = {
  // ...
  my_action: {
    key: 'my_action',
    path: 'open',                    // open | shadow | social | career
    name: '兴修水利',
    desc: '……',
    cost: { mandate: 3, silver: 120 },
    cooldown: 1,                     // 冷却回合数
    target: 'player',                // 可选，需指定对象时设置
    require: (ctx) => (ctx.target ? null : '须择一人。'),  // 返回字符串即拒绝
    resolve: (ctx) => ({
      effects: { merit: 20, renown: 10 },
      targetEffects: { favor: 5 },   // 对目标的效果
      relations: [{ to: ctx.target.id, type: 'ally', delta: 10 }],
      logs: ['……'],
    }),
  },
};
```

`ctx` 提供：`player` `rankId` `stats` `resources` `target` `targetName` `relationTo(id,type)` `patron`。

### 加一个官阶

在 `RANKS` 数组里插入一项，`id` 连续，`slots: null` 表示不限员额。
`initOfficeSlots()` 会自动补建占缺记录（`INSERT OR IGNORE`，重启不重复）。

### 加一个事件模板

往 `EVENT_TEMPLATES` 里加一项，指定 `weight` 与 `minRank`/`maxRank` 官阶区间即可。
